JSON to Swift Struct: Generating Codable Types from API Responses

Swift's Codable protocol (Encodable + Decodable) makes JSON serialization straightforward: conform your struct to Codable and JSONDecoder handles the rest. When you have a JSON response from an API, generating the Swift struct with proper optionality gives you a type-safe model you can pass directly to JSONDecoder().decode() — no manual key mapping, no unsafe casting.

Live Example: REST API Response

// Input JSON
{
  "product_id": "prd_7721",
  "name": "AirPods Pro",
  "price": 249.99,
  "in_stock": true,
  "rating": 4.8,
  "review_count": 14203,
  "description": null
}

// Generated Swift Struct
struct Root: Codable {
    let product_id: String
    let name: String
    let price: Double
    let in_stock: Bool
    let rating: Double
    let review_count: Double
    let description: String?
}

Idiomatic Swift: CodingKeys for snake_case Mapping

Swift conventions use camelCase. Use CodingKeys to map snake_case JSON to camelCase Swift, and fix Double → Int for count fields:

import Foundation

struct Product: Codable {
    let productId: String
    let name: String
    let price: Double
    let inStock: Bool
    let rating: Double
    let reviewCount: Int          // Int not Double for counts
    let description: String?      // nil when JSON is null

    enum CodingKeys: String, CodingKey {
        case productId   = "product_id"
        case name
        case price
        case inStock     = "in_stock"
        case rating
        case reviewCount = "review_count"
        case description
    }
}

// Or use JSONDecoder's keyDecodingStrategy (avoids manual CodingKeys for pure snake_case):
let decoder = JSONDecoder()
decoder.keyDecodingStrategy = .convertFromSnakeCase
// "product_id" → productId, "in_stock" → inStock automatically

let product = try decoder.decode(Product.self, from: jsonData)
print("\(product.name) — $\(product.price)")

Fetching JSON with async/await (iOS 15+)

import Foundation

struct ProductApiClient {
    private let decoder: JSONDecoder = {
        let d = JSONDecoder()
        d.keyDecodingStrategy = .convertFromSnakeCase
        d.dateDecodingStrategy = .iso8601
        return d
    }()

    func fetchProduct(id: String) async throws -> Product {
        let url = URL(string: "https://api.example.com/products/\(id)")!
        let (data, response) = try await URLSession.shared.data(from: url)

        guard let httpResponse = response as? HTTPURLResponse,
              httpResponse.statusCode == 200 else {
            throw URLError(.badServerResponse)
        }

        return try decoder.decode(Product.self, from: data)
    }
}

// In a SwiftUI ViewModel
@MainActor
class ProductViewModel: ObservableObject {
    @Published var product: Product?
    @Published var error: String?
    private let client = ProductApiClient()

    func load(productId: String) async {
        do {
            product = try await client.fetchProduct(id: productId)
        } catch {
            self.error = error.localizedDescription
        }
    }
}

SwiftUI Integration with @Observable (iOS 17+)

import SwiftUI
import Observation

@Observable
class ProductStore {
    var product: Product?
    var isLoading = false
    var errorMessage: String?

    func fetchProduct(id: String) async {
        isLoading = true
        defer { isLoading = false }

        do {
            let url = URL(string: "https://api.example.com/products/\(id)")!
            let (data, _) = try await URLSession.shared.data(from: url)
            product = try JSONDecoder().decode(Product.self, from: data)
        } catch {
            errorMessage = error.localizedDescription
        }
    }
}

struct ProductDetailView: View {
    @State private var store = ProductStore()
    let productId: String

    var body: some View {
        Group {
            if store.isLoading {
                ProgressView()
            } else if let product = store.product {
                VStack {
                    Text(product.name).font(.title)
                    Text("$\(product.price, specifier: "%.2f")")
                }
            }
        }
        .task { await store.fetchProduct(id: productId) }
    }
}

Swift struct vs class for API Models

  • struct (value type): Copied when assigned or passed — mutations don't propagate unexpectedly. Preferred for API models, DTOs, and view state. No reference counting overhead. Use this for JSON-decoded models.
  • class (reference type): Shared identity — multiple variables can point to the same instance. Use when you need shared mutable state (e.g., a singleton service, ObservableObject, or an object with inheritance). Codable works equally well with classes, but value semantics make structs safer for models.
  • Type fix: The generator uses Double for all JSON numbers. Change review_count, rank, and similar count fields to Int after generation.

Frequently Asked Questions

What's the difference between Codable, Encodable, and Decodable? Codable is a typealias for Encodable & Decodable. If you only need to decode (API responses), conforming to Decodable is sufficient. If you only need to encode (sending requests), use Encodable. Use Codable when you need both.

How does Swift handle missing vs null JSON keys? A String? (optional) property accepts both an explicit null and a missing key — both result in nil. A non-optional String property throws a DecodingError.keyNotFound if the key is absent. Make fields optional (T?) when the API might omit them.

What about dates in JSON? Set decoder.dateDecodingStrategy = .iso8601 and declare the property as Date — the decoder parses ISO 8601 strings automatically. For Unix timestamps, use .secondsSince1970 or .millisecondsSince1970.

Is my JSON sent to a server? No. TypeMorph runs entirely in your browser — none of your data leaves your machine.
