# Feature Spec: Feedback Widget (Discord/X導線の置き換え)

## 1. 背景・目的

現在の`FeedbackModal.tsx`は、「フィードバックを送る」ボタンを押すとDiscordサーバーへの参加リンクとX(Twitter)のプロフィールへの外部リンクが表示されるだけで、実際にフィードバックを直接送信する手段がない。

これには2つの問題がある。

- ユーザーがフィードバックを送るには「外部アプリへ移動する」「コミュニティに参加する」という複数ステップが必要で、心理的・手間的ハードルが高く、離脱しやすい。
- 仮にDiscordに書き込まれても、チャットログに埋まるだけで構造化されたデータにならず、集計・分析ができない。

この機能では、Discord/Xへの外部リンクを撤去し、**アプリ内で直接フィードバックを送信できる仕組み**に置き換える。

## 2. やりたいことの具体像

2つの仕組みを作る。

### 2-1. 埋め込みフィードバックフォーム(`FeedbackModal`の置き換え)

今のDiscord/Xボタンの代わりに、モーダル内に直接テキストエリアを置き、ワンクリックで送信できるようにする。送信されたフィードバックはどこかに保存され、後から確認できる必要がある(保存先の具体的な設計は実装者に委ねる、セクション5参照)。

### 2-2. 文脈付きミニフィードバック(新規・各機能に紐づける)

ユーザーが何か具体的な結果を見た直後(例: Breaking Change Detectorの結果表示、生成されたコードの表示)に、その場で「役に立ったか」を軽く聞けるウィジェットを追加する。サムズアップ/ダウンのような最小限の操作で答えられるものとし、自由記述は任意(必須にしない)。

これにより、「何が良かった/良くなかったか」を機能ごとに紐づけて集計できるようにする。

どの機能(Breaking Change Detector、各言語の生成結果、Quality Score等)にこのミニフィードバックを設置するかは、実装者がUIの自然さを考慮して判断してよい。最初は1〜2箇所への設置で構わない(全機能に一気に展開する必要はない)。

## 3. Discord/Xリンクの扱いについて

Discord/Xへのリンク自体は完全に削除してよい。「フィードバックを送る手段」としては撤去するが、コミュニティを作りたいという意図自体は否定しない。もし実装者が「コミュニティへの入り口」として別の自然な形(フッターのリンク等、既存の`GlobalFooter.tsx`にDiscordリンクは既にあるため重複を避ける)で残す価値があると判断するなら、その判断は委ねる。ただし**フィードバックモーダルの主要な導線としては使わない**こと。

## 4. 再利用する既存資産

- `src/lib/supabase.ts` — Supabaseクライアントが既に存在する。フィードバックの保存先として活用できないか検討する。
- `functions/api/verify.ts`, `functions/api/fetch-url.ts` — Cloudflare Workers形式のAPIエンドポイントの既存パターン。新しいエンドポイント(例: `functions/api/feedback.ts`)を追加する場合、この既存パターンに沿うこと。
- `src/components/FeedbackModal.tsx` — 置き換え対象。
- `src/components/GlobalFooter.tsx` — 既にDiscordリンクが含まれている可能性があるため、内容を確認し、重複した導線を作らないこと。

## 5. 設計判断は実装者(Opus)に委ねる部分

- フィードバックの保存先(既存のSupabaseテーブルを使うか、新規テーブルを作るか、別の軽量な方法を使うか)
- ミニフィードバックをどの機能に、どういうUIで設置するか
- 送信時のレート制限・スパム対策が必要かどうか、必要な場合どう実装するか
- 送信されたフィードバックをぽぽ自身がどう確認するか(Supabaseの管理画面で見るだけで十分か、通知が必要か等)

## 6. スコープの境界

**今回やること**
- `FeedbackModal.tsx`からDiscord/Xリンクを削除し、埋め込みフォームに置き換える
- 1〜2箇所への文脈付きミニフィードバックの設置

**今回やらないこと**
- フィードバックの分析・ダッシュボード機能(集計や可視化)は別フェーズ。まずは「送れて、どこかに保存される」状態を作ることを優先する。
- 既存のDiscordサーバー自体の運用方針の変更(これは製品機能ではなく運用の話のため対象外)。

## 7. プライバシー原則との整合性

この機能はユーザーが入力した自由記述テキストをサーバー(Supabase)に送信する。これは`PRIVACY_PRINCIPLES.md`の判断フロー上、「ユーザーが明示的に選択した結果の送信」に該当するため問題ない。ただし、何が送信されるかをユーザーに分かるようにすること(例: 送信ボタンの近くに「このフィードバックは開発者に送信されます」等、送信される事実を明示する)。

## 8. 受け入れ条件

- Discord/Xへの外部リンクが`FeedbackModal.tsx`から削除されていること。
- フィードバックフォームから送信した内容が、実際にどこかに保存され、後からぽぽが確認できる状態になっていること(実装後、ぽぽ自身が一度テスト送信して確認する)。
- 既存のテストが壊れないこと。
