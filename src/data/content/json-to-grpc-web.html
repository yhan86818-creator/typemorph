JSON to gRPC-Web: Connect-ES, Buf CLI, Browser Streaming, and TypeScript Client Generation

gRPC-Web brings gRPC's type-safe, binary-efficient communication to browsers — but the traditional setup (protoc + grpc-web plugin + Envoy proxy) has been replaced by a better stack: Buf CLI for schema management, @bufbuild/protoc-gen-es for type generation, and Connect-ES for a browser-native gRPC-Web client that works without an Envoy proxy. Connect uses standard HTTP/1.1 or HTTP/2, handles JSON and binary encoding, and produces TypeScript clients from .proto files that feel like calling regular async functions.

syntax = "proto3";
package transactions.v1;

import "google/protobuf/timestamp.proto";

enum TransactionStatus {
  TRANSACTION_STATUS_UNSPECIFIED = 0;
  TRANSACTION_STATUS_PENDING     = 1;
  TRANSACTION_STATUS_COMPLETED   = 2;
  TRANSACTION_STATUS_FAILED      = 3;
}

message Party {
  string account_id = 1;
  string name       = 2;
}

message Transaction {
  string            transaction_id = 1;
  int64             amount         = 2;
  string            currency       = 3;
  TransactionStatus status         = 4;
  Party             sender         = 5;
  Party             receiver       = 6;
  google.protobuf.Timestamp created_at = 7;
}

message GetTransactionRequest  { string transaction_id = 1; }
message ListTransactionsRequest {
  string account_id = 1;
  int32  page_size  = 2;
  string page_token = 3;
}
message ListTransactionsResponse {
  repeated Transaction transactions = 1;
  string next_page_token            = 2;
}

service TransactionService {
  rpc GetTransaction(GetTransactionRequest)       returns (Transaction);
  rpc ListTransactions(ListTransactionsRequest)   returns (ListTransactionsResponse);
  rpc WatchTransactions(GetTransactionRequest)    returns (stream Transaction);
}

Connect-ES Client: Browser Usage

// Generated by buf generate:
// src/generated/transactions/v1/transactions_pb.ts — message types
// src/generated/transactions/v1/transactions_connect.ts — service definition

import { createClient } from "@connectrpc/connect";
import { createConnectTransport } from "@connectrpc/connect-web";
import { TransactionService } from "./generated/transactions/v1/transactions_connect";
import type { Transaction } from "./generated/transactions/v1/transactions_pb";

// Create transport — no Envoy proxy needed for Connect protocol
const transport = createConnectTransport({
  baseUrl: "https://api.example.com",
  // Optional: use JSON encoding instead of binary for debugging
  // useBinaryFormat: false,
});

const client = createClient(TransactionService, transport);

// Unary RPC — async/await
const transaction = await client.getTransaction({ transactionId: "txn_abc123" });
console.log(transaction.amount);      // 2500n (BigInt for int64)
console.log(transaction.currency);    // "USD"
console.log(transaction.sender.name); // "Acme Corp"

// List with typed response
const { transactions, nextPageToken } = await client.listTransactions({
  accountId: "acc_001",
  pageSize:  20,
});
console.log(transactions.length);     // typed: Transaction[]

Server Streaming: Real-Time Data

// Server streaming — ideal for real-time dashboards
// The server sends multiple Transaction messages over a single connection

async function watchTransactions(accountId: string, onUpdate: (t: Transaction) => void) {
  const abortController = new AbortController();

  try {
    for await (const transaction of client.watchTransactions(
      { transactionId: accountId },
      { signal: abortController.signal }
    )) {
      // Each iteration receives one Transaction message from the server
      onUpdate(transaction);
    }
  } catch (err) {
    if (err instanceof ConnectError && err.code === Code.Canceled) {
      return; // AbortController signal — normal cancellation
    }
    console.error('Stream error:', err);
  }

  return () => abortController.abort(); // cleanup function
}

// React hook for real-time transaction updates
import { useEffect, useState } from 'react';
import { ConnectError, Code } from "@connectrpc/connect";

function useTransactionStream(accountId: string) {
  const [transactions, setTransactions] = useState<Transaction[]>([]);

  useEffect(() => {
    const abortController = new AbortController();

    (async () => {
      for await (const txn of client.watchTransactions(
        { transactionId: accountId },
        { signal: abortController.signal }
      )) {
        setTransactions(prev => [txn, ...prev.slice(0, 49)]); // keep last 50
      }
    })().catch(err => {
      if (!(err instanceof ConnectError && err.code === Code.Canceled)) {
        console.error('Stream error:', err);
      }
    });

    return () => abortController.abort(); // cancel on unmount
  }, [accountId]);

  return transactions;
}

Node.js Server Implementation with Connect

// Server using Connect for Node.js (no gRPC-Web proxy needed)
// npm install @connectrpc/connect @connectrpc/connect-node @bufbuild/protobuf

import { createServer } from "@connectrpc/connect-node";
import { http2 } from "http2";
import { TransactionService } from "./generated/transactions/v1/transactions_connect";
import type { Transaction } from "./generated/transactions/v1/transactions_pb";

const routes = (router: { service: Function }) => {
  router.service(TransactionService, {
    async getTransaction(req) {
      const row = await db.transactions.findOne({ where: { id: req.transactionId } });
      return {
        transactionId: row.id,
        amount:        BigInt(row.amount_cents),
        currency:      row.currency,
        status:        mapStatus(row.status),
        sender:        { accountId: row.sender_id,   name: row.sender_name },
        receiver:      { accountId: row.receiver_id, name: row.receiver_name },
        createdAt:     { seconds: BigInt(Math.floor(row.created_at.getTime() / 1000)) },
      };
    },

    async *watchTransactions(req) {
      // Subscribe to change events and yield new transactions
      const subscription = eventBus.subscribe(`transactions.${req.transactionId}`);
      try {
        for await (const event of subscription) {
          yield event.transaction as Transaction;
        }
      } finally {
        subscription.unsubscribe();
      }
    },
  });
};

http2.createServer(createServer({ routes })).listen(8080);

Best Practices for Production

  • Use Connect-ES instead of the legacy grpc-web package: The grpc-web npm package requires an Envoy proxy between the browser and the gRPC server because it uses a custom protocol (not standard HTTP/2 gRPC). Connect-ES uses the HTTP Connect protocol which works over standard HTTP/1.1 and HTTP/2 directly — no proxy required, no extra infrastructure.
  • Use buf.build remote plugins instead of local protoc: Installing and maintaining protoc + multiple plugins manually is fragile. Buf's remote plugins always run the correct version, don't require local installation, and produce consistent output across environments. buf generate handles everything.
  • Cancel server streams with AbortController on component unmount: A streaming RPC keeps an HTTP connection open. In React, failing to abort it on unmount means the stream continues consuming network and server resources after navigation. Return () => abortController.abort() from useEffect.
  • Use JSON encoding during development, binary in production: Connect-ES supports both application/json and application/proto encoding. Set useBinaryFormat: false in your dev transport to make requests/responses readable in browser DevTools. Switch to binary in production for ~30% smaller payloads.

FAQ

Q: gRPC-Web vs REST+JSON — when is gRPC-Web worth the complexity?
A: gRPC-Web pays off when: (1) you control both client and server, (2) you need server streaming or bidirectional streaming, (3) payload efficiency matters (mobile clients, high-frequency data), or (4) you want compile-time API contract enforcement across frontend/backend. For public APIs, simple CRUD, or when the backend is third-party, REST+JSON is simpler and more compatible.

Q: Can I use Connect-ES with an existing gRPC server that doesn't support Connect?
A: Yes — Connect-ES's createGrpcWebTransport and createGrpcTransport work with standard gRPC servers. Use createConnectTransport only when the server also uses Connect. If your server uses standard gRPC, use createGrpcWebTransport which requires a proxy like Envoy or grpc-web-proxy.

Q: How do I handle authentication in gRPC-Web with Connect-ES?
A: Use interceptors — a Connect-ES middleware layer that runs before/after each request. Create an auth interceptor that adds the Authorization header: const authInterceptor = (next) => async (req) => { req.header.set('Authorization', 'Bearer ' + token); return next(req); }. Pass it to the transport: createConnectTransport({ baseUrl, interceptors: [authInterceptor] }).
