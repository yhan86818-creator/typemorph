JSON to Effect Schema: Effect エコシステムによる型安全なバリデーション

Effect Schema（Effect ライブラリの一部）は TypeScript 向けの次世代スキーマバリデーションライブラリです。Zod がバリデーション専用であるのに対し、Effect Schema は Effect の代数的エフェクトシステムと深く統合されており、型付きエラーハンドリング・依存性注入・非同期ワークフローとの組み合わせが得意です。JSON を Effect Schema に変換することで、ランタイムの安全性と Effect エコシステム全体へのアクセスが手に入ります。

実例: JSON から Effect Schema へ

// 入力 JSON
{
  "user_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "email": "alice@example.com",
  "age": 28,
  "created_at": "2024-01-15T09:00:00Z",
  "tags": ["admin", "verified"],
  "address": { "city": "Tokyo", "zip": "160-0022" }
}

// 生成された Effect Schema
import { Schema } from "effect";

const AddressSchema = Schema.Struct({
  city: Schema.String,
  zip: Schema.String,
});

const UserSchema = Schema.Struct({
  user_id: Schema.UUID,
  email: Schema.String.pipe(Schema.pattern(/^[^@]+@[^@]+\.[^@]+$/)),
  age: Schema.Int,
  created_at: Schema.DateTimeUtc,
  tags: Schema.Array(Schema.String),
  address: AddressSchema,
});

export type User = Schema.Schema.Type<typeof UserSchema>;

// 同期デコード（失敗時は例外を投げる）
const user = Schema.decodeSync(UserSchema)(json);

// Effect として（構造化エラーハンドリング）
const decoded = Schema.decode(UserSchema)(json);

セットアップ手順

1. Effect をインストール： npm install effect。Effect Schema は effect パッケージに同梱されているため、追加のインストールは不要です。
2. Schema をインポート： import { Schema } from "effect"
3. JSON を貼り付け TypeMorph に JSON サンプルを入力し、Effect Schema を選択して生成します。
4. データをデコード： シンプルなバリデーションには Schema.decodeSync、Effect パイプラインの中では Schema.decode を使います。
5. 型を推論： Schema.Schema.Type<typeof YourSchema> で TypeScript 型を自動取得できます。

技術解説: Effect Schema vs Zod

Effect Schema と Zod は同じ問題を異なるアプローチで解決します。Zod はスタンドアローンで初学者にも優しく、どこでも最小限のセットアップで使えます。Effect Schema は Effect エコシステムの中で真価を発揮し、非同期/エラー管理にすでに Effect を使っている場合に特に強力です。最大の違いは、Effect Schema の decode が Effect を返すこと—失敗が型付きの代数的な値として表現されるため、try/catch ではなく Effect.catchTag や Effect.match で構造的に処理できます。また、Effect Schema は双方向変換（TS → JSON のエンコードと JSON → TS のデコード）を同一スキーマで表現できます。

主要な組み込みスキーマ

Effect Schema には精密なブランド型が揃っています。Schema.UUID は文字列を検証しつつ UUID としてブランド化します。Schema.DateTimeUtc は ISO 8601 文字列を Date ではなく DateTime.Utc インスタンスにパースするため、タイムゾーンを意識した日時演算が可能です。Schema.Int は数値が整数であることを検証し、Schema.NullOr は nullable フィールドをクリーンに扱います。

比較: Effect Schema vs Zod vs Valibot

Effect Schema は Effect の全スタック（Effect for async、Layer for DI）でビルドしている場合に最適です。Zod は最も広く使われており、tRPC・React Hook Form・OpenAPI など豊富なインテグレーションがあります。Valibot はツリーシェイキングによるバンドルサイズの小ささが特徴で、クライアントサイドのパフォーマンス重視のアプリに向いています。

ベストプラクティス

  • 本番では Schema.decodeSync より Schema.decode を使う： 非同期版は型付き Effect を返し、例外の代わりに構造化されたエラーハンドリングが得られます。
  • ブランド型を活用する： Schema.UUID は検証だけでなく、出力型を string & Brand<"UUID"> としてブランド化します。これにより、UUID が必要な場所に任意の文字列を渡す誤りをコンパイル時に防げます。
  • pipe でスキーマを合成する： Schema.String.pipe(Schema.minLength(1), Schema.maxLength(255)) のようにチェーンできます。
  • 循環参照には Schema.suspend を使う： 自己参照スキーマ（ツリーノードなど）は Schema.suspend(() => NodeSchema) で循環依存を解消します。

よくある質問

Q: Schema だけ使いたいのに Effect ライブラリ全体をインストールしなければなりませんか？
A: はい—Effect Schema は effect パッケージの一部です。バンドルサイズは Zod より大きいですが、すでに Effect を非同期処理に使っているなら追加コストはありません。

Q: Effect のパイプラインなしで Effect Schema だけ使えますか？
A: はい。Schema.decodeSync を使えば Effect パイプライン不要で同期バリデーションができます。段階的な導入が可能です。

Q: オプショナルフィールドはどう扱いますか？
A: オプショナルには Schema.optional(Schema.String)、nullable には Schema.NullOr(Schema.String) を使います。両方の場合は Schema.NullOr(Schema.optional(Schema.String)) で表現できます。
