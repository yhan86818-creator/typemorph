JSON to Styled Components: ThemeProvider, TypeScript Theme Types, and Dark Mode

Styled Components' ThemeProvider injects a theme object into every styled component via React context, making JSON design tokens the single source of truth for colors, spacing, typography, and breakpoints. The professional setup requires three things that most examples skip: TypeScript's DefaultTheme augmentation for fully typed props.theme access, a well-structured JSON token file that aligns with Styled Components' theme object shape, and a dark mode strategy that switches the entire theme object (not just individual color variables) when toggled. This guide covers all three, plus createGlobalStyle, css helpers, and keyframes.

// tokens.ts — convert JSON to typed theme
import tokens from './design-tokens.json';

export const lightTheme = {
  colors: {
    brand:   tokens.colors.brand,
    text:    tokens.colors.text,
    bg:      tokens.colors.bg,
    border:  tokens.colors.border,
    error:   tokens.colors.error,
    success: tokens.colors.success,
  },
  spacing:    tokens.spacing,
  radii:      tokens.radii,
  shadows:    tokens.shadows,
  fontFamily: tokens.fontFamily,
  fontSize:   tokens.fontSize,
} as const;

export const darkTheme = {
  ...lightTheme,
  colors: {
    ...lightTheme.colors,
    text:   { primary: '#f9fafb',   secondary: '#9ca3af', inverse: '#111827' },
    bg:     { default: '#111827',   surface:   '#1f2937', overlay: '#374151' },
    border: '#374151',
  },
} as const;

export type AppTheme = typeof lightTheme;

// types/styled.d.ts — augment DefaultTheme for full type safety
import 'styled-components';
import type { AppTheme } from '../tokens';

declare module 'styled-components' {
  export interface DefaultTheme extends AppTheme {}
}

// App.tsx — inject theme at root
import { useState } from 'react';
import { ThemeProvider, createGlobalStyle } from 'styled-components';
import { lightTheme, darkTheme } from './tokens';

const GlobalStyle = createGlobalStyle`
  *, *::before, *::after { box-sizing: border-box; }
  body {
    margin: 0;
    font-family: ${({ theme }) => theme.fontFamily.sans};
    font-size:   ${({ theme }) => theme.fontSize.base};
    color:       ${({ theme }) => theme.colors.text.primary};
    background:  ${({ theme }) => theme.colors.bg.default};
    transition:  background 0.2s ease, color 0.2s ease;
  }
`;

export function App() {
  const [isDark, setIsDark] = useState(false);
  const theme = isDark ? darkTheme : lightTheme;

  return (
    <ThemeProvider theme={theme}>
      <GlobalStyle />
      <button onClick={() => setIsDark(!isDark)}>Toggle Theme</button>
      {/* All children have typed access to props.theme */}
    </ThemeProvider>
  );
}

Fully Typed Styled Components

import styled, { css } from 'styled-components';

// Button with typed theme props — no 'any'
type ButtonVariant = 'primary' | 'secondary' | 'ghost';

interface ButtonProps {
  variant?: ButtonVariant;
  size?:    'sm' | 'md' | 'lg';
  disabled?: boolean;
}

const sizeStyles = {
  sm: css`padding: ${({ theme }) => theme.spacing['1']} ${({ theme }) => theme.spacing['3']};
          font-size: ${({ theme }) => theme.fontSize.sm};`,
  md: css`padding: ${({ theme }) => theme.spacing['2']} ${({ theme }) => theme.spacing['4']};
          font-size: ${({ theme }) => theme.fontSize.base};`,
  lg: css`padding: ${({ theme }) => theme.spacing['3']} ${({ theme }) => theme.spacing['6']};
          font-size: ${({ theme }) => theme.fontSize.lg};`,
};

export const Button = styled.button<ButtonProps>`
  display:         inline-flex;
  align-items:     center;
  justify-content: center;
  border:          none;
  border-radius:   ${({ theme }) => theme.radii.md};
  font-family:     ${({ theme }) => theme.fontFamily.sans};
  cursor:          ${({ disabled }) => disabled ? 'not-allowed' : 'pointer'};
  transition:      background 0.15s, opacity 0.15s;
  opacity:         ${({ disabled }) => disabled ? 0.5 : 1};

  ${({ size = 'md' }) => sizeStyles[size]}

  ${({ variant = 'primary', theme }) =>
    variant === 'primary' ? css`
      background: ${theme.colors.brand};
      color:      ${theme.colors.text.inverse};
      &:hover:not(:disabled) { filter: brightness(1.1); }
    ` :
    variant === 'secondary' ? css`
      background: ${theme.colors.bg.surface};
      color:      ${theme.colors.text.primary};
      border:     1px solid ${theme.colors.border};
      &:hover:not(:disabled) { background: ${theme.colors.bg.overlay}; }
    ` : css`
      background: transparent;
      color:      ${theme.colors.brand};
      &:hover:not(:disabled) { background: ${theme.colors.bg.surface}; }
    `}
`;

// Card component
export const Card = styled.div`
  background:    ${({ theme }) => theme.colors.bg.surface};
  border:        1px solid ${({ theme }) => theme.colors.border};
  border-radius: ${({ theme }) => theme.radii.lg};
  box-shadow:    ${({ theme }) => theme.shadows.sm};
  padding:       ${({ theme }) => theme.spacing['4']};
`;

Dark Mode with System Preference

// Detect system dark mode preference and sync with ThemeProvider
import { useState, useEffect } from 'react';

function useSystemTheme(): 'light' | 'dark' {
  const [theme, setTheme] = useState<'light' | 'dark'>(
    () => window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
  );

  useEffect(() => {
    const mq = window.matchMedia('(prefers-color-scheme: dark)');
    const handler = (e: MediaQueryListEvent) => setTheme(e.matches ? 'dark' : 'light');
    mq.addEventListener('change', handler);
    return () => mq.removeEventListener('change', handler);
  }, []);

  return theme;
}

export function App() {
  const systemTheme = useSystemTheme();
  const [override, setOverride] = useState<'light' | 'dark' | null>(null);
  const activeTheme = override ?? systemTheme;

  return (
    <ThemeProvider theme={activeTheme === 'dark' ? darkTheme : lightTheme}>
      <GlobalStyle />
      <ThemeToggle
        current={activeTheme}
        onToggle={() => setOverride(prev => !prev || prev === 'light' ? 'dark' : 'light')}
      />
    </ThemeProvider>
  );
}

Best Practices for Production

  • Always augment DefaultTheme for TypeScript: Without the styled.d.ts declaration file, props.theme is typed as DefaultTheme = {} — accessing any property is a TypeScript error. After augmentation, every styled component has fully typed theme access with autocomplete and error checking.
  • Switch the whole theme object for dark mode, not individual values: Define two complete theme objects (lightTheme, darkTheme) and swap them in ThemeProvider. This is cleaner than a single theme with conditional logic inside components, and it keeps the token file readable.
  • Use the css helper for conditional styles: The css tagged template literal properly handles interpolations inside conditional expressions, ensuring correct TypeScript inference and preventing issues with Styled Components' tagged template parsing.
  • Migrate to Styled Components v6 before 2026: Styled Components v6 drops support for IE11, enables Babel's new transform, and improves server-side rendering. If you're on v5, plan the migration — the API is mostly backward compatible but has breaking changes around StyleSheetManager and SSR setup.

FAQ

Q: Styled Components vs CSS Modules vs Tailwind — when to choose each?
A: Styled Components excels for component libraries where styles are co-located with components, dynamic styling based on props is frequent, and TypeScript integration matters. CSS Modules are better for performance-sensitive apps (zero runtime, static extraction). Tailwind is best when you want utility-first rapid prototyping without a styling abstraction layer. For a design-system-driven app with a JSON token pipeline, Styled Components is the most ergonomic choice.

Q: Does Styled Components support server-side rendering?
A: Yes, via ServerStyleSheet and StyleSheetManager. Next.js requires additional configuration in _document.tsx (Pages Router) or a custom plugin (App Router). With React Server Components (RSC), Styled Components has runtime overhead — consider Linaria or vanilla-extract for RSC-compatible static extraction.

Q: How do I avoid re-renders caused by theme changes?
A: ThemeProvider only triggers re-renders for components that actually read from props.theme. Memoize your theme object with useMemo so it doesn't create a new object reference on every render, which would cause all themed components to re-render unnecessarily.
