cURL to Fetch: Complete Flag Reference, TypeScript Wrapper, AbortController, and Streaming

Translating cURL commands to the Fetch API requires understanding the mapping between cURL's flag-based syntax and Fetch's options object — including the non-obvious cases like basic auth (-u), multipart uploads (-F), compressed responses (--compressed), cookie jars (-c / -b), and response streaming. Beyond direct translation, a production Fetch setup needs an AbortController timeout pattern, a typed response handler, and centralized error handling. This guide covers the full cURL→Fetch mapping plus a reusable TypeScript HTTP client built on top of it.

cURL Flag Reference: Complete Mapping

// curl -u username:password https://api.example.com/resource
fetch('https://api.example.com/resource', {
  headers: {
    'Authorization': 'Basic ' + btoa('username:password'),
  },
});

// curl -H "Authorization: Bearer eyJhbGci..." https://api.example.com/me
fetch('https://api.example.com/me', {
  headers: { 'Authorization': 'Bearer eyJhbGci...' },
});

// curl -X PATCH --data-raw '{"status":"active"}' URL
fetch(URL, {
  method:  'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body:    '{"status":"active"}',

// curl -X DELETE URL
fetch(URL, { method: 'DELETE' });

formData.append('caption', 'My Photo');

  method:  'POST',

    'Accept':    'application/json',
  },

// ─── Response compression ─────────────────────────────────────

// Browsers and Fetch handle this automatically — no option needed.
// Node.js Fetch (18+) also handles it automatically.

// curl -L URL              (follow redirects — default behavior)

AbortController: Timeout and Cancellation

// cURL has --max-time 30 for timeout — Fetch requires AbortController

// Basic timeout
function fetchWithTimeout(url: string, options: RequestInit = {}, ms = 30_000): Promise<Response> {
  const controller = new AbortController();
  const timeout    = setTimeout(() => controller.abort(new Error(`Timeout after ${ms}ms`)), ms);

  return fetch(url, { ...options, signal: controller.signal })
    .finally(() => clearTimeout(timeout));
}

// React: cancel request when component unmounts
import { useEffect, useState } from 'react';

function useData<T>(url: string) {
  const [data,  setData]  = useState<T | null>(null);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    const controller = new AbortController();

    fetch(url, { signal: controller.signal })
      .then(res => {
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return res.json() as Promise<T>;
      })
      .then(setData)
      .catch(err => {
        if (err.name !== 'AbortError') setError(err);
      });

    return () => controller.abort();   // cleanup: cancel on unmount
  }, [url]);

  return { data, error };
}

// Retry with exponential backoff (no cURL equivalent — cURL has --retry)
async function fetchWithRetry(url: string, options: RequestInit = {}, maxRetries = 3): Promise<Response> {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      const response = await fetchWithTimeout(url, options);
      if (response.status === 429 || response.status >= 500) {
        if (attempt < maxRetries) {
          await new Promise(r => setTimeout(r, 2 ** attempt * 1000));
          continue;
        }
      }
      return response;
    } catch (err) {
      if (attempt === maxRetries) throw err;
      await new Promise(r => setTimeout(r, 2 ** attempt * 1000));
    }
  }
  throw new Error('unreachable');
}

TypeScript API Client Pattern

// Production-ready typed Fetch wrapper
class ApiClient {
  private baseUrl:    string;
  private headers:    Record<string, string>;
  private timeoutMs:  number;

  constructor(baseUrl: string, options: {
    apiKey?:    string;
    timeoutMs?: number;
  } = {}) {
    this.baseUrl   = baseUrl.replace(/\/$/, '');
    this.timeoutMs = options.timeoutMs ?? 30_000;
    this.headers   = {
      'Content-Type': 'application/json',
      'Accept':       'application/json',
      ...(options.apiKey ? { 'Authorization': `Bearer ${options.apiKey}` } : {}),
    };
  }

  private async request<T>(path: string, init: RequestInit = {}): Promise<T> {
    const controller = new AbortController();
    const timeout    = setTimeout(() => controller.abort(), this.timeoutMs);

    try {
      const response = await fetch(`${this.baseUrl}${path}`, {
        ...init,
        headers:  { ...this.headers, ...init.headers },
        signal:   controller.signal,
      });

      if (!response.ok) {
        const body = await response.text().catch(() => '');
        throw new ApiError(response.status, response.statusText, body);
      }

      const contentType = response.headers.get('Content-Type') ?? '';
      if (contentType.includes('application/json')) {
        return response.json() as Promise<T>;
      }
      return response.text() as unknown as T;
    } finally {
      clearTimeout(timeout);
    }
  }

  get<T>(path: string, params?: Record<string, string>): Promise<T> {
    const url = params ? `${path}?${new URLSearchParams(params)}` : path;
    return this.request<T>(url);
  }

  post<T>(path: string, body: unknown): Promise<T> {
    return this.request<T>(path, { method: 'POST', body: JSON.stringify(body) });
  }

  patch<T>(path: string, body: unknown): Promise<T> {
    return this.request<T>(path, { method: 'PATCH', body: JSON.stringify(body) });
  }

  delete<T>(path: string): Promise<T> {
    return this.request<T>(path, { method: 'DELETE' });
  }
}

class ApiError extends Error {
  constructor(
    public status: number,
    public statusText: string,
    public body: string,
  ) {
    super(`HTTP ${status} ${statusText}: ${body}`);
    this.name = 'ApiError';
  }
}

// Usage
const api = new ApiClient('https://api.example.com', { apiKey: 'secret' });
const user = await api.get<User>('/users/123');
const created = await api.post<User>('/users', { name: 'Alice' });

Streaming Responses (Server-Sent Events / NDJSON)

// curl -N URL    (no buffering — stream response line by line)

// Browser: Stream a text/event-stream (SSE) or NDJSON response
async function* streamResponse(url: string, body: unknown) {
  const response = await fetch(url, {
    method:  'POST',
    headers: { 'Content-Type': 'application/json' },
    body:    JSON.stringify(body),
  });

  if (!response.ok || !response.body) {
    throw new Error(`HTTP ${response.status}`);
  }

  const reader  = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';   // keep incomplete last line in buffer

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        yield JSON.parse(line.slice(6));   // SSE format: "data: {...}"
      } else if (line.trim()) {
        yield JSON.parse(line);            // NDJSON format: raw JSON per line
      }
    }
  }
}

// Usage with an LLM streaming API
for await (const chunk of streamResponse('/api/chat', { message: 'Hello' })) {
  process.stdout.write(chunk.text ?? '');
}

Best Practices for Production

  • Check response.ok explicitly: Unlike cURL, which exits with a non-zero code on HTTP errors, fetch() only rejects on network failure. A 404 or 500 response resolves successfully. Always check if (!response.ok) throw new ApiError(response.status, ...); before reading the body.
  • Don't set Content-Type when sending FormData: The browser must set this header itself to include the multipart boundary string (multipart/form-data; boundary=----WebKitFormBoundary...). Setting it manually breaks the request — the boundary won't match the actual body.
  • Use credentials: 'include' only when you control the server: This sends cookies cross-origin, which requires the server to explicitly set Access-Control-Allow-Credentials: true and a specific Access-Control-Allow-Origin (not *). For third-party APIs, omit credentials entirely.
  • Cancel requests in React/Vue components with AbortController: Failing to cancel fetch requests on component unmount causes state updates on unmounted components, React warnings, and potential race conditions in navigation-heavy apps. Return () => controller.abort() from useEffect.

FAQ

Q: Why does my fetch succeed in Node.js/cURL but fail in the browser with a CORS error?
A: cURL and Node.js HTTP calls don't have CORS restrictions — they're not subject to the Same-Origin Policy. Browser Fetch sends an Origin header with every cross-origin request, and the server must respond with matching Access-Control-Allow-Origin headers. The fix is always on the server side (or a proxy), not in the fetch call. Adding mode: 'no-cors' doesn't help — it only suppresses the error by returning an opaque response you can't read.

Q: What's the Fetch equivalent of curl -v for debugging?
A: Browser DevTools' Network tab shows the full request/response including headers. In Node.js, use the --verbose flag with undici's setGlobalDispatcher, or use the fetch-intercept package for logging. For production debugging, attach request IDs to every request in the X-Request-ID header and correlate with server logs.

Q: Fetch vs Axios — which should I use in 2024?
A: Native Fetch is the right default for browser and Node.js 18+ projects — no dependencies, works everywhere, supports streaming. Use Axios when you need interceptors (request/response middleware for token refresh), automatic JSON serialization of non-200 responses as errors, or older browser compatibility without a polyfill. For TypeScript projects, the ApiClient wrapper above gives you most of Axios's ergonomic benefits with zero dependencies.
