FIX to JSON: Tag-Value Parsing, Dictionary Lookup, Checksum Validation, and FIXML Alternative

Converting FIX protocol messages to JSON enables storage in document databases, debugging with standard JSON tools, integration with REST-based compliance systems, and feeding analytics pipelines. The conversion has three technical requirements beyond basic string splitting: checksum validation (Tag 10 must be verified before any processing), data dictionary lookup (tag numbers like 35 must be mapped to msgType, not just carried forward as numeric keys), and repeating group parsing (groups like NoOrders=382 produce nested arrays, not flat key-value pairs). The standard delimiter in live FIX is SOH (\x01) but documentation and test fixtures typically use | or \n.

function validateChecksum(message: string): boolean {
  const soh = '\x01';
  const normalized = message.replace(/\|/g, soh);

  // Checksum tag (10=xxx\x01) must be at the end
  const checksumMatch = normalized.match(/\x0110=(\d+)\x01$/);
  if (!checksumMatch) return false;

  const receivedChecksum = parseInt(checksumMatch[1], 10);
  const bodyEnd          = normalized.length - checksumMatch[0].length;
  const body             = normalized.slice(0, bodyEnd + 1);  // include last SOH before checksum tag

  let sum = 0;
  for (let i = 0; i < body.length; i++) sum += body.charCodeAt(i);

  return (sum % 256) === receivedChecksum;
}

function fixToJson(rawMessage: string, validateCrc = true): object {
  const delimiter = rawMessage.includes('\x01') ? '\x01' : '|';
  const pairs     = rawMessage.split(delimiter).filter(Boolean);
  const result: Record<string, unknown> = {};

  if (validateCrc && !validateChecksum(rawMessage)) {
    throw new Error('FIX checksum validation failed — message may be corrupted');
  }

  for (const pair of pairs) {
    const eqIdx = pair.indexOf('=');
    if (eqIdx === -1) continue;

    const tag = pair.slice(0, eqIdx);
    const val = pair.slice(eqIdx + 1);
    const def = FIX_DICT[tag];

    const key        = def?.name ?? `tag${tag}`;
    const readableVal = def?.readable?.[val];

    result[key] = readableVal ?? val;

    // Preserve raw numeric value alongside readable label
    if (readableVal) {
      result[`${key}_raw`] = val;
    }
  }

  return result;
}

Batch Conversion: FIX Drop Copy Log to NDJSON

// Process a file of FIX messages (one per line or SOH-delimited)
// and write as NDJSON for BigQuery/Snowflake ingestion

import { createReadStream, createWriteStream } from 'fs';
import { createInterface } from 'readline';

async function fixLogToNdjson(inputPath: string, outputPath: string): Promise<void> {
  const input  = createReadStream(inputPath, 'utf-8');
  const output = createWriteStream(outputPath);
  const rl     = createInterface({ input });

  let processed = 0;
  let errors    = 0;

  for await (const line of rl) {
    if (!line.trim()) continue;
    try {
      const parsed = fixToJson(line, false);  // skip checksum for archived logs
      output.write(JSON.stringify(parsed) + '\n');
      processed++;
    } catch (e) {
      console.warn(`Line ${processed + errors + 1}: ${(e as Error).message}`);
      errors++;
    }
  }

  output.end();
  console.log(`Processed: ${processed}, Errors: ${errors}`);
}

await fixLogToNdjson('./drop-copy.log', './drop-copy.ndjson');

// Parsing FIXML to JSON: use fast-xml-parser with attribute flattening
import { XMLParser } from 'fast-xml-parser';

const xmlParser = new XMLParser({
  ignoreAttributes:    false,
  attributeNamePrefix: '',   // flatten attributes directly
  removeNSPrefix:      true,
});

function fixmlToJson(fixml: string): object {
  return xmlParser.parse(fixml);
}

Best Practices for Production

  • Always validate the checksum (Tag 10) before processing: The checksum catches message corruption during transmission. Calculate the sum of all bytes (including SOH delimiters) from the start of the message to the 10= tag, mod 256. A mismatch means the message was corrupted and should trigger a resend request, not be processed as valid data.
  • Map to human-readable values AND preserve raw values: The Side field value '1' should be stored as { side: 'Buy', side_raw: '1' }. Downstream systems need the human-readable form for display, but regulatory audit trails and round-trip conversion back to FIX require the original raw value.
  • Normalize the SOH delimiter before splitting: Real FIX messages use \x01 (ASCII 01). Documentation, test fixtures, and logging systems replace it with |, \n, or ^A. Detect which delimiter is present (if \x01 exists, use it; otherwise try |) before splitting.
  • Use structured logging (JSON) for all FIX traffic in compliance systems: Financial regulators (SEC, FINRA, MiFID II) require complete records of all order-related messages. Store the parsed JSON alongside the raw FIX string. Include a timestamp of when the message was received, the parser version, and the source IP to create a complete audit record.

FAQ

Q: Is the FIX checksum secure for data integrity?
A: No — the Tag 10 checksum (sum mod 256) detects accidental corruption but provides no protection against malicious modification. For security in FIX sessions, use FIX over TLS (mutual authentication), session-level encryption, or additional application-layer MACs. The checksum is a transmission reliability check, not a security control.

Q: How do I handle FIX messages with custom tags (above 5000)?
A: Custom tags are institution-specific extensions. Load a custom FIX dictionary (XML format matching the official FIX repository schema) that adds your counterparty's custom tags alongside standard ones. Most FIX libraries accept custom dictionaries at initialization. Without the dictionary, represent custom tags as tag5001: "value" rather than losing them.

Q: Can I convert JSON back to a valid FIX message?
A: Yes, but you must recalculate Tag 9 (body length) and Tag 10 (checksum) — they cannot be preserved from the JSON because they depend on the final byte sequence. Build the tag-value pairs in the required order (header first: 8, 9, 35; then body; then trailer: 10), join with SOH, calculate the body length and checksum, and insert them at the correct positions.
